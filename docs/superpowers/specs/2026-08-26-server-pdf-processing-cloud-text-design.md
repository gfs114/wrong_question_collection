# 错题收集云端 PDF 处理与服务器主数据设计

**日期：** 2026-08-26
**状态：** 已完成方案讨论，等待书面规格确认
**适用工程：** `G:\code\openHarmony\wrong_question_collection`

## 1. 目标

将现有端侧 PDF 渲染、OCR、切题和裁图流程迁移到云服务器。题库、题目、答案、解析和错题状态以服务器 MySQL 为唯一主数据源；HarmonyOS 客户端可以下载文字缓存供离线查看，但离线时不能修改业务数据。

题图只保存在创建导入任务的设备。服务器在处理期间临时保存 PDF 和题图，设备成功下载并确认后立即删除；没有收到确认时最多保留 24 小时。其他设备只能同步文字，并明确显示“本设备无原题图片”。

## 2. 明确不做

- 不在服务器长期保存 PDF 原文件或题图。
- 不把题图同步到其他设备。
- 不在离线状态创建题库、编辑题目、添加错题或修改掌握状态。
- 不继续使用本地 outbox 作为新架构的写入路径。
- 不为当前单机部署引入 Redis、对象存储或多 Worker 集群。
- 不承诺把数学公式完整识别成可编辑文本；低置信度内容必须保留题图并进入人工确认。

## 3. 总体架构

系统采用“服务器主数据、客户端只读缓存、设备私有题图”的边界。

### 3.1 HarmonyOS 客户端

- 选择 PDF、计算文件哈希并执行分片上传。
- 查询服务器导入进度，展示服务端 OCR 草稿并允许在线审核修改。
- 确认后从服务器下载属于当前设备的临时题图，并保存到应用私有目录。
- 维护服务器题目 UUID 到本机题图路径的设备私有映射。
- 在线时从服务器增量刷新文字缓存。
- 离线时只读取缓存，禁用所有会改变服务器状态的操作。
- 不再执行 PDF 页面渲染、OCR、切题或题图裁剪。

### 3.2 NestJS API

- 验证华为账号会话、用户和设备身份。
- 管理分片上传、最终哈希校验、导入任务状态和取消操作。
- 提供 OCR 草稿读取与在线修改接口。
- 在用户确认时使用 MySQL 事务写入正式题库文字。
- 只允许创建任务的用户和原设备下载临时题图。
- 接收设备下载确认并触发立即清理。
- 定期回收超过 24 小时的 PDF、分片和题图。

### 3.3 Python OCR Worker

- 作为独立 Docker 容器运行，不嵌入 NestJS API 进程。
- 使用 MySQL 任务队列领取任务；当前部署固定单并发。
- 使用 PDFium 渲染、PaddleOCR 中文模型、OpenCV/Pillow 完成 OCR、版面分析、切题和裁图。
- 将文字草稿、置信度和处理进度写入 MySQL。
- 将临时题图写入受控临时卷，数据库只保存不可猜测的 artifact ID 和服务器生成的相对标识。
- 容器以非 root 身份、只读根文件系统、无外网、有限 CPU/内存运行，仅临时工作目录可写。

### 3.4 MySQL 任务队列

当前只有一台服务器和一个 Worker，因此直接使用 MySQL 8.4 队列，避免增加 Redis 运维成本。Worker 使用短事务领取任务，并通过锁定状态防止重复处理。任务失败最多自动重试两次；超过次数后保留明确错误分类，等待用户手动重试或取消。

## 4. 数据模型

### 4.1 新增表

`import_jobs`

- `id`：任务 UUID。
- `user_id`、`device_id`：所有权与题图下载范围。
- `bank_name`、`subject`、`page_start`、`page_end`。
- `status`：`uploading`、`queued`、`processing`、`review`、`confirmed`、`failed`、`cancelled`、`expired`。
- `progress_current`、`progress_total`、`error_code`。
- `source_sha256`、`source_size`、`retry_count`。
- `created_at`、`updated_at`、`expires_at`。

`import_upload_parts`

- 任务 ID、分片编号、大小、SHA-256、接收时间。
- 任务内分片编号唯一。
- 合并完成后删除分片记录和分片文件。

`import_draft_questions`

- 草稿 UUID、任务 ID、顺序、题型、题干、选项、答案、解析。
- 原始页码范围、OCR 置信度、是否需要人工确认。
- 草稿修改只允许任务所属用户在线完成。

`import_artifacts`

- artifact UUID、任务 ID、类型、服务器生成的存储键、大小、SHA-256、过期时间。
- 类型仅允许 `source_pdf`、`question_image` 和必要的处理临时文件。
- 不接受客户端提供的服务器路径。

### 4.2 现有正式业务表

用户确认草稿时，服务器在一个事务中写入现有 `question_banks`、`questions` 及关联文字数据。题图不进入正式云端业务表。每道正式题目返回稳定 UUID，客户端使用该 UUID 绑定本机图片。

### 4.3 客户端缓存

本地缓存保存：

- 当前账号 ID 和服务器数据版本。
- 题库、题目、答案、解析、错题状态的只读副本。
- 服务器题目 UUID 到本机题图路径的映射。
- 当前设备创建的导入任务恢复信息。

本地映射必须按账号隔离。退出登录后清除文字缓存与会话，但不立即删除题图；题图对其他账号不可见。原账号重新登录后可以重新关联。用户明确删除本机数据或账号时再清理对应题图。

## 5. 接口设计

所有接口均使用现有 Bearer Access Token，并从服务端会话确定用户和设备，客户端不能提交 `userId` 或冒充其他设备。

```text
POST   /v1/imports/pdf
PUT    /v1/imports/pdf/:jobId/parts/:partNumber
POST   /v1/imports/pdf/:jobId/complete
GET    /v1/imports/pdf/:jobId
GET    /v1/imports/pdf/:jobId/draft
PATCH  /v1/imports/pdf/:jobId/draft
POST   /v1/imports/pdf/:jobId/confirm
GET    /v1/imports/pdf/:jobId/images/:artifactId
POST   /v1/imports/pdf/:jobId/ack
POST   /v1/imports/pdf/:jobId/retry
DELETE /v1/imports/pdf/:jobId
```

上传采用固定大小分片。每个分片携带 SHA-256，完成请求携带整个 PDF 的 SHA-256 和分片总数。服务器校验分片完整性、最终文件大小、PDF 文件签名和页数范围后，才把任务从 `uploading` 切换为 `queued`。

`confirm` 先保存正式文字并返回题目 UUID 与 artifact UUID 对照表。题图下载失败不回滚已经确认的文字；客户端在 24 小时窗口内继续下载。`ack` 必须列出已验证落盘的 artifact UUID，服务器仅在任务所需图片全部确认后立即删除源 PDF、题图和剩余临时文件。

## 6. PDF 导入状态流

```text
uploading → queued → processing → review → confirmed
     │          │          │          │
     └──────────┴──────────┴──────────┴→ cancelled
                           │
                           └→ failed → queued（最多自动重试两次）

任一终态超过 expires_at → expired → 清理临时文件
```

应用被关闭或网络中断不会改变任务所有权。重新进入后，客户端通过任务 ID 查询进度并恢复上传、审核或图片下载。任务状态更新使用条件更新，避免取消和 Worker 完成互相覆盖。

## 7. 在线与离线行为

在线状态：

- 所有新建、编辑、删除、添加错题和掌握状态变更直接提交服务器。
- 服务器成功响应后再更新本地缓存。
- 请求失败时不伪造本地成功，不产生新的 outbox。

离线状态：

- 允许浏览已缓存文字和本机已有题图。
- 所有写入按钮禁用并显示“连接网络后可修改”。
- PDF 导入只能在恢复网络后开始或继续。
- 服务器不可用时不清空最后一次成功缓存。

## 8. 现有数据迁移

迁移以不丢数据为首要条件：

1. 升级后保留现有数据库和题图，不立即删除旧表或 outbox。
2. 用户登录后按题库分批把现有本地文字上传服务器。
3. 服务端幂等接收并返回题库、题目 UUID。
4. 客户端在事务中建立旧本地题目与服务器题目 UUID 的对应关系，并重新绑定题图。
5. 从服务器重新下载并核对文字缓存数量和内容摘要。
6. 全部核验成功后标记迁移完成，停止读取旧可写业务表和旧 outbox。
7. 旧表先保留一个应用版本作为恢复来源；后续版本再通过独立、可回滚的清理迁移删除。

任何一步失败都保持旧数据可读取并允许重试。不同账号不得认领同一份未迁移本地数据；首次迁移前必须向用户明确将数据绑定到当前华为账号。

## 9. 安全与资源限制

- PDF 最大 200MB，单任务最多处理连续 20 页。
- 校验 MIME、PDF 魔数、最终哈希、页数和解析结果，不执行 PDF 内嵌脚本或外部引用。
- 分片、PDF 和题图均存入服务器生成的任务目录，禁止路径穿越和符号链接逃逸。
- API 不返回真实服务器路径、命令行、堆栈或 OCR 模型内部错误。
- Worker 不共享 API 的环境密钥，不持有华为 Client Secret 或 JWT 签名密钥。
- Caddy 设置上传体积、请求时长和并发限制；API 与 Worker 分别设置 CPU、内存和日志上限。
- 任务完成确认后立即清理；未确认任务在 24 小时后清理。
- 定时清理同时核对 MySQL 记录和临时卷，处理孤儿文件但不扫描或删除容器挂载范围外的路径。
- 磁盘达到安全水位时拒绝新上传，但不影响现有文字浏览和账号接口。

## 10. 错误分类

客户端只接收稳定错误码和中文可操作提示：

- `UPLOAD_INCOMPLETE`：缺少分片，可继续上传。
- `FILE_HASH_MISMATCH`：文件校验失败，需要重新选择或上传。
- `PDF_INVALID`：不是有效 PDF 或无法解析。
- `PDF_ENCRYPTED`：加密 PDF 不支持。
- `PAGE_RANGE_INVALID`：页码范围无效或超过 20 页。
- `OCR_FAILED`：OCR 任务失败，可手动重试。
- `OCR_REVIEW_REQUIRED`：结果存在低置信度内容，需要人工确认。
- `ARTIFACT_EXPIRED`：临时题图已过期，只保留文字。
- `DEVICE_NOT_OWNER`：当前设备无权下载该任务题图。
- `SERVER_STORAGE_PRESSURE`：服务器空间不足，暂时拒绝新任务。

## 11. 测试与验收

### 11.1 服务端

- 数据库迁移、任务状态机、并发领取、幂等确认和 24 小时清理测试。
- 分片缺失、重复分片、哈希错误、越权下载和设备冒充测试。
- 文本 PDF、扫描 PDF、中文数学 PDF、损坏 PDF、加密 PDF 和超大 PDF Worker 测试。
- Worker 崩溃、API 重启、MySQL 短暂不可用和磁盘水位测试。

### 11.2 HarmonyOS

- ArkTS 契约测试和 API 26 HAP 构建。
- 真机验证分片中断恢复、应用后台重进、任务轮询、在线审核和题图落盘。
- 验证离线页面只读、写入按钮禁用、缓存不因网络错误被清空。
- 验证退出登录后的账号隔离以及原账号重新登录后的题图恢复。

### 11.3 多设备

- 设备 A 导入并保存文字与图片；设备 B 只获得文字并显示缺图提示。
- 设备 B 在线修改文字后，设备 A 刷新缓存且本机题图映射保持有效。
- 设备 A 确认下载后服务器立即删除临时图；设备 B 无法下载。
- 未确认的任务在 24 小时后无法下载图片，但正式文字仍可使用。

## 12. 部署影响

在现有 Compose 中新增 `ocr-worker` 服务和受控临时卷。MySQL、API、Caddy、备份保持现有职责。当前 40GB 磁盘只长期保存 MySQL 文字数据；临时 PDF 和题图受 24 小时 TTL、任务数量和磁盘水位共同限制。

OCR 为 CPU 密集型。初始部署固定单并发，并在上线前通过真实 PDF 记录单页耗时、峰值内存和临时空间。若实际性能不足，再独立升级 CPU/内存或迁移 Worker，不提前引入 Redis 和集群。

## 13. 实施边界

实施必须分阶段进行：先新增服务器任务与 Worker，再新增客户端云端导入流程，随后迁移旧数据，最后停用端侧 OCR 和旧 outbox。任何阶段都不能先删除现有本地数据或题图。服务器接口、客户端缓存和迁移工具完成端到端验收后，才允许移除旧端侧处理代码。
