# PDF 题库导入设计

## 1. 背景与目标

现有应用仅支持导入结构严格的 JSON 单选题题库。本功能增加 PDF 导入，并优先适配纯扫描数学资料。用户可以从本地选择 PDF、指定科目和页码范围，在设备端完成页面渲染、文字识别、题目切分、结果校对和本地保存。

本功能的目标如下：

- 支持文字型和扫描型 PDF。
- 支持单选题、填空题、计算题和证明题等混合题型。
- 单次由用户选择连续页码范围，最多处理 20 页。
- 保存题目原图裁剪，避免复杂数学公式因 OCR 失真而丢失。
- OCR 文本用于搜索、编辑和题型判断，不作为公式内容的唯一依据。
- 答案和解析均为可选字段，不影响题目保存。
- 全部处理和数据存储均在设备端完成。

参考样本为 `2026考研数学-张宇1000题数一（习题分册）.pdf`。该文件共 166 页、约 65 MB、无密码，抽查页面均无可提取文字层，包含大量公式及混合题型。

## 2. 范围与非目标

### 2.1 首版范围

- 通过 `DocumentViewPicker` 选择单个 PDF。
- 题库名称默认取文件名，允许用户修改。
- 导入前必须选择科目。
- 用户选择起始页和结束页，单次最多 20 页。
- 使用 PDF Kit 将页面逐页转换为 `PixelMap`。
- 使用 Core Vision Kit 在端侧逐页 OCR。
- 根据题号和 OCR 文字位置自动裁剪题目原图。
- 自动判断单选题、填空题和解答题，允许用户在确认页修改。
- 支持跨页题目关联多张原图。
- 支持取消、部分页面失败和识别结果编辑。
- 保存后可在题目详情页查看原图和 OCR 文本。

### 2.2 非目标

- 不识别或生成标准 LaTeX、MathML 等数学公式文本。
- 不提供云端 OCR、云端大模型或服务器同步。
- 不自动生成答案或解析。
- 不保证任意版式均能自动准确切题。
- 不在模拟器上验证 OCR 效果；Core Vision Kit OCR 需要真机。
- 不改变现有严格 JSON 导入规则。

## 3. 方案选择

### 3.1 采用方案

所有选中页面统一执行“PDF 转图片后端侧 OCR”。文字型和扫描型 PDF 共用一套处理路径：

```text
选择 PDF
  -> 流式复制到应用临时目录
  -> 读取 PDF 页数并选择页码范围
  -> 逐页转换 PixelMap
  -> 逐页端侧 OCR
  -> 根据题号位置切分并裁剪原图
  -> 合并跨页题目
  -> 识别题型和结构化字段
  -> 用户确认与编辑
  -> 事务保存题库、题目和图片关联
```

该方案不依赖 PDF 文字层，能够覆盖参考样本。逐页串行处理可以限制峰值内存，代价是文字型 PDF 的处理速度低于直接提取文字。

### 3.2 未采用方案

#### 文字层优先、OCR 兜底

该方案处理文字型 PDF 更快，但文字层阅读顺序不稳定，并需要额外文本解析能力。参考样本完全没有文字层，因此首版收益有限。

#### 内置 PDFium 和独立 OCR 模型

该方案控制能力更强，但会增加安装包体积、C/C++ 开发量、模型资源和设备适配成本，不适合首版。

#### 云端 OCR 或大模型

该方案可以提升复杂版式理解能力，但需要服务器、网络权限、密钥管理、隐私说明和持续费用，与已确认的全端侧要求不符。

## 4. 用户交互

### 4.1 导入入口

现有“导入题库”页面保留 JSON 导入，并增加独立的“导入 PDF”入口。两种导入方式的校验规则互不影响。

### 4.2 PDF 设置页

选择文件后显示：

- 文件名和总页数。
- 默认题库名称，来源为去除扩展名的 PDF 文件名。
- 可修改的题库名称。
- 必填科目选择。
- 起始页和结束页输入。
- 已选页数提示；超过 20 页时禁止开始。

### 4.3 识别进度页

识别过程中显示当前阶段、当前页和总页数，例如“正在识别第 3/12 页”。页面提供取消按钮。取消后停止调度下一页，并清理本次产生的临时文件。

处理采用单页串行方式：渲染一页、OCR、切分和保存临时裁剪后，立即释放该页 `PixelMap`。

### 4.4 识别结果确认页

结果以题目卡片列表显示：

- 一张或多张题目原图。
- OCR 题干。
- OCR 选项。
- 题型。
- 可选答案。
- 可选解析。
- 来源页码。
- 识别状态。

用户可以修改全部文字字段、切换题型、删除误识别题目。答案和解析为空不构成错误。只有题干切分失败、内容为空或题型无法判断时显示“待确认”。

自动切分完全失败的页面不会被丢弃，而是整页作为一条“待确认题目”进入确认页。

### 4.5 保存与详情

保存时以事务写入题库、题目和图片关联。详情页优先展示原题图片，并在下方展示 OCR 文字、选项、答案和解析。答案为空时显示“未填写”，解析为空时显示“暂无解析”。

删除题库时，数据库记录与应用沙箱内对应图片一并删除。

## 5. 题目识别规则

### 5.1 题目边界

优先识别位于行首的阿拉伯数字题号，例如 `1.`、`2．`、`23、`。裁剪区域从当前题号所在行开始，到下一题题号所在行之前结束。

需要排除页眉中的章节号和页脚页码。规则综合使用文字位置、字号区域、页面边缘距离及同页连续题号判断。

### 5.2 跨页题目

如果页面末尾题目未在本页结束，则下一页第一题号之前的区域作为同一题的后续图片。单个题目可以关联多张按顺序排列的图片，避免强行拼接造成超长位图和额外内存占用。

### 5.3 题型判断

- 识别到至少两个连续的 `(A)`、`A.`、`A．` 等选项标记时，初步判断为 `single_choice`。
- 没有选项但存在明显填空线或题干括号时，初步判断为 `fill_blank`。
- 其他题目判断为 `short_answer`。
- 规则置信不足时标记为 `unclassified` 和“待确认”。

用户可以在确认页修改题型。答案不是题型判断或保存的必要条件。

### 5.4 OCR 文本定位

OCR 文本只承担题号定位、选项提取、搜索文本和辅助编辑。数学公式、矩阵、积分、上下标等内容以原图为准，不尝试在首版中生成可编辑公式格式。

## 6. 数据模型与数据库

数据库版本从 1 升级到 2。已有表和数据保留。

### 6.1 题目表

现有 `question.type` 继续存储字符串，并扩展允许值：

- `single_choice`
- `fill_blank`
- `short_answer`
- `unclassified`

现有 `answer` 和 `analysis` 列保持 `TEXT NOT NULL`，缺失值使用空字符串，因此无需为可选答案修改列约束。

新增字段：

- `source_page_start INTEGER NOT NULL DEFAULT 0`
- `source_page_end INTEGER NOT NULL DEFAULT 0`
- `review_state TEXT NOT NULL DEFAULT 'confirmed'`

`review_state` 允许 `confirmed` 和 `needs_review`。该状态与答案是否为空无关。

### 6.2 题目图片表

新增 `question_image`：

```sql
CREATE TABLE question_image (
  id TEXT PRIMARY KEY,
  question_id TEXT NOT NULL,
  page_number INTEGER NOT NULL,
  image_path TEXT NOT NULL,
  sort_order INTEGER NOT NULL
)
```

为 `question_id` 创建索引。每道题可以关联多张图片，用于跨页题目。

### 6.3 文件存储

临时 PDF 和中间页面图像位于应用缓存目录。最终题目裁剪图位于应用文件目录下按题库隔离的子目录。图片采用有损压缩并限制长边尺寸，以控制存储占用；原始 PDF 不长期保留。

数据库提交失败时删除本次已生成的最终图片。题库删除完成后清理对应图片目录。

## 7. 服务边界

建议新增或扩展以下职责：

- `PdfImportService`：文件选择结果、流式复制、PDF 打开、页数与页码校验、任务取消和生命周期清理。
- `PdfPageRenderer`：PDF Kit 页面转换、像素尺寸约束和 `PixelMap` 释放。
- `OnDeviceOcrService`：Core Vision Kit 初始化、逐页识别、释放和能力错误映射。
- `PdfQuestionParser`：题号检测、题型判断、字段提取、跨页合并和待确认回退。
- `QuestionImageService`：裁剪图压缩、暂存、提交、回滚和题库图片清理。
- `QuestionBankService`：支持版本 2 数据结构、图片关联查询、题目编辑和事务保存。

解析器使用明确的 ArkTS 类和类型，不使用动态对象、`any`、`unknown` 或类型断言。现有 `JsonParser` 保持不变。

## 8. 错误处理

- 文件超过 200 MB：导入前拒绝并提示文件过大。
- 文件损坏、格式错误或无法打开：清理临时文件，不写入数据库。
- 加密 PDF：首版不要求用户输入密码，提示暂不支持。
- 页码越界、倒序或超过 20 页：禁止开始识别。
- OCR 能力不支持：提示需要支持该能力的鸿蒙真机。
- 单页 OCR 失败：记录失败页，继续处理后续页。
- 页面无法切题：保留整页并标记待确认。
- 用户取消：不调度下一页，释放当前资源，清理本次临时文件。
- 图片或数据库保存失败：数据库事务回滚并清理已写入图片。
- 存储空间不足：提示释放空间后重试，不保留半成品题库。

## 9. 性能与资源约束

- 单次最多 20 页。
- PDF 文件上限 200 MB，使用流式读写。
- 页面严格串行处理，避免同时持有多张全页 `PixelMap`。
- OCR 与裁剪完成后立即释放整页像素资源。
- 题目图片限制分辨率并压缩，避免长期保存全分辨率扫描页。
- 进度状态可见，任务允许取消。

## 10. 测试与验收

### 10.1 单元测试

- 页码范围与 20 页限制。
- 文件名到题库名称的规范化。
- 题号检测及页眉、页脚排除。
- 单选题、填空题、解答题分类。
- 选项提取和空答案处理。
- 跨页题目合并及图片顺序。
- 无法切题时的整页回退。
- 取消、部分页面失败和清理状态机。
- 数据库版本 1 到 2 的迁移。
- 保存失败后的事务和图片回滚。

### 10.2 构建验证

- 每次 `.ets` 修改后执行 ArkTS 检查。
- 执行 Hypium 测试。
- 执行 debug HAP 构建。
- 检查应用未新增网络权限。

### 10.3 真机验收

由于端侧 OCR 不支持模拟器，最终验收需要鸿蒙真机：

- 选择参考 PDF 并读取 166 页总页数。
- 选择不超过 20 页的范围。
- 检查逐页进度和取消。
- 检查选择题、填空题和解答题切分。
- 检查数学公式原图可读。
- 检查跨页题目多图顺序。
- 检查空答案题目可以保存。
- 删除题库后检查图片文件同步清理。

## 11. 云端说明

本方案不需要云端服务，不上传 PDF 或题目图片，不添加网络权限，不产生 OCR API 费用。所有 OCR、裁剪、编辑和存储均在设备端完成。
